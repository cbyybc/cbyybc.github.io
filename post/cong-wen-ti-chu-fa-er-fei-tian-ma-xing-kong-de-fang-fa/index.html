从问题出发，而非天马行空的方法

2026-11-09 4 min read

这一点应该是理论专业和计算机/AI这样一个实验学科最大的区别了。

如果仅靠灵光一现的想法，而没有对问题有一个充分的了解，那么多半会是浪费时间。

当然不得不喷的还有AI的选题，你不质疑自己可能完全发现不到问题。

最近决定结束一个持续了一段时间的研究项目。虽然完成了不少实验和开发工作，但最终还是放弃了最初的研究方向。

项目最初的设想是利用大模型 Agent 自动检测并修复三维网格缺陷。当时更多考虑的是技术可行性：有没有合适的数据和工具，如何设计系统，怎样通过多轮交互提高修复能力。直到真正开始实验，才逐渐意识到研究动机本身存在问题。

第一个转折来自强模型的表现。

原本以为需要专门设计 Agent 才能解决的几何问题，Astra 在少量实验中已经能够通过生成代码和调用传统算法完成。甚至有些任务只需要直接判断无需修改。虽然这远不足以证明网格修复已经被解决，但至少说明，我们预想的技术难点未必真正存在。

第二个转折来自弱模型的对照实验。

既然强模型已经具备相当不错的能力，我们开始考虑通过 Agent 提升弱模型。然而实验发现，弱模型的主要困难甚至不是几何修复本身，而是工具使用、任务规划和最终提交。这让研究方向逐渐偏离几何算法，变成了如何弥补当前模型的通用能力缺陷。

第三个转折来自评价体系。

即使模型修复后的网格在几何上完全合法，也不意味着它符合原本的设计意图。要可靠地评价修复质量，就需要明确的设计真值和足够完善的 Benchmark。而构建这些数据本身，又意味着大量额外工作。

回头看，项目的研究目标从几何修复逐渐转向 Agent 增强、模型能力评测，甚至知识蒸馏。每一次调整都有合理的动机，但也暴露出最初选题时没有回答的根本问题：

即使最终成功了，我们究竟解决了什么现有方法没有解决好的问题？

这次最大的失误，不是没有提前预测到模型的能力，也不是缺少现成的数据集，而是没有充分验证研究问题的价值，就过早投入了工程实现。

科研当然不可能在开始之前排除所有不确定性。但至少应该先了解最强基线的能力边界，明确评价标准，并尝试用最简单的实验推翻自己的设想，而不是等投入大量时间后才开始寻找创新点。

这次项目没有得到最初期待的结果，却让我重新认识了科研中最重要、也最容易被忽略的一步：选题。

工程能力决定一个想法能被实现到什么程度，而科研判断力决定这个想法是否值得实现。

前者AI已经能达到95%的水平了，而后者才是科研者需要重点研究的部分了。
